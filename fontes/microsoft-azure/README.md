## Como as fontes são utilizadas

As referências oficiais são usadas para:

1. verificar a definição técnica de cada recurso;
2. confirmar diferenças entre serviços;
3. identificar APIs e formas de integração;
4. verificar idiomas e localidades suportados;
5. registrar limitações e requisitos;
6. acompanhar mudanças de produto;
7. evitar informações desatualizadas em um projeto de portfólio;
8. relacionar a formação oficial concluída aos conteúdos documentados no repositório.

## Distinção entre formação, documentação e prática

Este repositório utiliza três níveis de referência:

**Formação certificada:** cursos e módulos Microsoft Learn concluídos pela autora.

**Documentação técnica:** informações oficiais utilizadas para explicar o funcionamento e as possibilidades dos serviços.

**Execução prática:** resultados que somente devem ser registrados quando houver ambiente, execução e evidência reais. A autora não dispõe de uma assinatura Azure para este projeto; portanto, não são apresentados testes, métricas, capturas ou resultados experimentais fictícios.

## Ciclo de vida

A documentação da Microsoft deve ser consultada continuamente porque serviços de IA evoluem. A página de ciclo de vida informa versões, depreciações e datas de aposentadoria. Recursos conversacionais, em especial, podem sofrer mudanças de produto; por isso, novos projetos devem sempre considerar a documentação atual e as recomendações de migração da Microsoft.

## Critério de confiabilidade

Para informações técnicas específicas, a prioridade deste projeto é:

1. documentação oficial da Microsoft;
2. referências oficiais de API/SDK;
3. Microsoft Learn e materiais educacionais oficiais;
4. fontes secundárias somente quando usadas para contexto.

## Observação

Links de documentação podem mudar com a evolução da plataforma. Por isso, o README registra os endereços oficiais e recomenda consultar as páginas atuais antes de implementar uma solução.
